# 面试提交 README 设计

状态：已批准并实施

## 目标

仓库根目录 `README.md` 作为唯一提交入口。评审打开 GitHub 后，应在首屏获得仓库地址、生产地址、参考视频和项目判断，并能按题目顺序定位五项实现说明。

## 信息结构

README 按评审阅读路径组织：

1. **提交信息**：GitHub 仓库、公开访问网址、参考视频、技术栈。
2. **快速验收**：一次主文章流式生成和一次章节 5W1H 操作。
3. **实现说明**：YouTube 字幕、Gemini 流式输出、用户要求、章节级 5W1H。
4. **主要工程取舍和亮点**：解释关键选择、替代方案和适用边界。
5. **运行、测试与部署**：保留可复现命令和凭据边界。
6. **延伸文档**：架构、输出协议、验证记录和两天计划继续留在 `docs/`，README 只提供结论与链接。

## 内容原则

- 保留代码、测试和生产烟测能够证明的事实。
- 不补造性能、成本、用户反馈和稳定性数据。
- 直接解释为什么选择 NDJSON、Durable Object、两阶段生成、字幕 Fixture 和 SOCKS5 TCP 隧道。
- 明确区分 YouTube 原始字幕、版本化演示字幕和 Gemini AI 视频转录。
- 免费额度与第三方能力只描述当前项目的使用方式；易变限制链接到官方资料，不作为项目保证。
- 主正文用中文，接口名、模块名和命令保持原始拼写。

## 修改范围

只重构 `README.md`。不修改业务代码、接口、页面、Cloudflare 配置和既有验证结果，也不新增内容重复的 `SUBMISSION.md`。

## 验收标准

- README 首屏包含两个可点击提交地址。
- 题目要求的五项说明均有独立标题，可通过目录快速定位。
- 快速验收步骤不依赖本地环境。
- 所有实现路径、测试数量、部署命令和外部链接与当前仓库一致。
- Markdown 链接有效，Mermaid 语法和代码块闭合。
- 文档不存在待完成标记、占位符或敏感凭据。
